## 2. 这次实验怎么设计

一次登录里，收到 `0x60CD` 后**连发 6 条不同内容的 `0xE13A`**（间隔 5 秒），
看哪一条之后客户端动界面 / 发新请求。

| # | 变体 | result | eff 记录 | zeon 记录 | bmg | tut | 正文长 | 想验证的假设 |
|---|---|---|---|---|---|---|---|---|
| 1 | `both` | 0 | id=5 `TEST` | id=6 `ZEON` | 0 | 0 | 817 | 基线：结构对、数据有效 |
| 2 | `res1` | **1** | id=5 | id=6 | 0 | 0 | 817 | `result` 必须非 0 才算成功 |
| 3 | `eff` | 0 | id=5 | 全零 | 0 | 0 | 817 | 只有一侧有机师也接受 |
| 4 | `tut` | 0 | id=5 | id=6 | 0 | **1** | 817 | `is_tutorial_end` 必须是 1 |
| 5 | `bmg1` | 0 | id=5 | id=6 | **1** | 0 | **840** | bmg 列表非空路径（顺带验证 840 字节帧） |
| 6 | `resm1` | **-1** | id=5 | id=6 | 0 | 0 | 817 | `result` 是错误码（`FUN_00439190` 首参 `if (-1 < result)`） |

字段布局按已定案的线格式（`fake_auth.pilot_entry`）：`+0 id(4)`、`+4 name[25]`、
`+33 troops`、`+34 level`、`+35 mil_class`，其余留 0。

## 2.5 第一次实跑结果（18:52）——**消息确实被处理了**

```
18:52:02  [pilot] 收到 0x60CD
18:52:02  [var 1] both  bodylen=817 帧头=0133033ae1 n=246..297
18:52:07  [var 2] res1  bodylen=817 帧头=0133033ae1 n=298..349
18:52:12  error: ConnectionAbortedError(10053)  ← **客户端主动断连**
18:52:12  closed 127.0.0.1:63612 (存活 16.2s, 共收 2912 字节)
```

客户端界面弹「服务器通信被切断了 (L0:0)」。

**这是全新的行为**：之前几轮发全零 817（`zero`）客户端都是一动不动地等到超时；
这次在 10 秒内主动断开 ⇒ 说明带**有效机师记录**的正文被解析后触发了断连。

但还分不清是 `both`（有效记录）还是 `res1`（result=1）触发的 —— 所以加了观察窗（见 §3）。

## 2.6 观察窗（已实现）

每发一个变体后，用 `select` + `recv(1, MSG_PEEK)`（**不消费字节**）盯 socket：

| 观察结果 | 含义 | 日志 |
|---|---|---|
| 有新数据待读 | **变体被接受，客户端追问了** | `>>> 对端有新数据待读 +x.xs` |
| EOF | 客户端断连（被拒/异常） | `>>> 对端在 x.xs 后关闭连接` |
| 超时 | 无任何反应 | `观察 12s：无任何反应` |

一旦出现"有新数据"或"断连"就停止后续变体（避免干扰），把连接交给接收循环。

## 2.7 第一次跑的判读与下一次的顺序

因为断连发生在 var1 之后、var2 发送成功之后，两个候选都还没排除，所以下一次用
**对照法**：先发已知"无反应"的 `zero` 作对照，再发 `both`，再发 `res1`……

当前 `start_local.cmd` 里是：`--pilot-variants zero,both,res1,eff --probe-gap 12.0`
## 2.8 第二次实跑（18:55）—— 对照组把原因夹住了 ★

```
18:55:44  [var 1] zero  bodylen=817
18:55:56  [var 1] 观察 12s：无任何反应            ← 全零正文：客户端完全不理会
18:55:56  [var 2] both  bodylen=817
18:55:56  [var 2] >>> 对端在 0.0s 后关闭连接      ← 有效机师记录：**立刻断连**
18:55:56  [pilot] 后续变体不再发送
```

- `zero` 与 `both` 唯一差别 = 机师记录里有没有 id/名字，反应完全相反
  ⇒ **`0xE13A` 已被完整解析，且被记录内容打中**。
- 断连后**没有重连**（日志尾部再无 accept）⇒ 客户端进了"通信中断"终态，
  不是协议切换（切换会重连）。

### 由此收窄的两种解释

1. `zero` = "成功但无事可做"（没有机师）；`both` 有 2 个机师 → 客户端进入
   "填卡片/显示机师"分支 → 分支里某处校验或查表失败 → 会话被拆掉；
2. 或者 `both` 触发了"数据非法 → 断开"的守卫。

两者都要先知道**哪个字段**触发，所以下一步拆单字段。
