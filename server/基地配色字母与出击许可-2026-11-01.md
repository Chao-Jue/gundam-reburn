# 基地配色、字母和出击许可的运行验证

本轮为 Windows UAC 授权后的当前客户端实验。未改服务器协议或持久客户端资源；内存实验重启即失效。CPS 启动已由用户在 hooked 中绕开，不把该信息当作业务数据正确的证据。

## 已观察到的缺失

- 四个标记绑定实体分别为 27000、27001、27002、27003；阵营为 0、0、1、1，没有重复实例绑定。
- 标记分类 22，角色 HP 为 100/100，但地图仍缺自动挂接。调用已有 454570 后产生四个标记。
- 游戏阵营 game+3A9CC 为 0。UI 配色对象（*(*01161F80+18)）的 +8C/+90 均为 0；用户覆盖配置 *01161F68+3C/+40 也为 0。
- 9EDDB0/9EDDD0 分别返回覆盖色或上述默认色。9EF860 注册的配置键为 zeon_ui_color、eff_ui_color；原资源值和未初始化原因尚未恢复。
- 用明确标为测试值的蓝红色填入默认色并执行 876820 后，用户确认己方凸形图标、满血血条均变蓝。颜色缺失已有实际因果验证。
- 四个角色 +C8 均为 255（未设置），不是同一个 ID。87D650 从 +C8 选择基地字母。按静态 post 的 +44 索引补入 0、1、0、1 并重绑后，用户确认己方显示 A、B。
- 原生 877760 要求角色阵营相符，且角色 +35C 组件存在、组件 +D2 的 bit0 为 1。四个组件最初均为 0；补 bit0 后己方资格检查为 1、敌方为 0。

## 为什么补许可后仍不能点

长时间调试后选择倒计时已结束。440770 返回 0，43F600 返回 1（机体已就绪），5E8A30 返回 0（无模态阻塞）。6229F0 检查 UI +100 的准备时间；当时为 0。临时写入 120 秒后 440770 返回 1。用户随后确认“能够选择并确认”。这只证明临时初始化后的基地选择闭环，不代表服务端实体出击或战斗完成。

## 工具与边界

- tools/probe_base_palette.py：只读快照，记录配色、实例、字母、许可和选择状态。
- tools/diagnose_base_palette.py：四基地守卫、仅零配色时写入明确的测试颜色并刷新。
- tools/diagnose_base_spawn_state.py：核对四个不同实体、定义 777201、静态字母索引后，临时填入字母和许可；需要时重开 120 秒选择时间。不是服务端正式实现。
- 先前第一次配色实验时客户端进程已退出，没有结果文件；重新进入后重试成功，不能将第一次算成功。
