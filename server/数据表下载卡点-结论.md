## 一句话结论

登录链路已经全部打通到 **「正在取得数据」**，卡在下载第 2 张服务端表
`msma/msma_weapon_set.csv`。这张表和后面 **72 张**在 27GB 解密资源包里不存在，
只存在于原服务端。

客户端**确实收到了并开始处理**这份数据（实测在处理期间分配了 200+ 块内存），
但**一行都没能收进表**，队列因此不推进，45 秒后掐线 → `L 2:0`。

**不是协议没打通，也不是分派错了，而是行级校验没过。而校验要的内容我们造不出来。**

## 一、已经走通的完整链路（可复现）

等待条：认证中 → 登录中 → 正在取得战区列表 → 选择世界 → 正在检索战区
→ 频道登录中 → **正在取得数据**（停）

| 阶段 | 客户端发 | 服务端回 | 关键点 |
|---|---|---|---|
| 握手 | 16B 密文 | 32B 密钥材料 | 前 16 = 下行，后 16 = 上行 |
| hello | `0x34A9` | `op_de24`（3×u32） | 首 u32 ≥ 0 ⇒ `[proto+0x3CC]=1` |
| 账号 | `0xF24B`（94B） | `op_a5da`（1×u32） | u32 ≥ 0 ⇒ LoginAuth 步骤 +1 |
| 取战区 | `0x8288` | `0x298E`（3×u32 + N×309B） | 载荷 323B 要用类型 1 宽度 |
| 选世界 | `0x3B8F` | `0x4F3F`（1×u32） | 0 = 无防沉迷剩余 |
| 检索战区 | `0xA380` | `0x1146` | 字符串是 C 串，必须紧挨着写 |
| 休息室 | 短 `0xF24B` | 休息室 `0xA5DA`（2×u32） | 与认证服同名不同义 |
| 取数据表 | `0xF86A` | `0x5290` | **卡在这里** |

上行帧头是**明文长度**（密文按 16 对齐），下行帧头是**密文长度**。

数据表共 **74 条**（`settings/download_list.csv`：75 行 = 1 表头 + 74 数据）：
第 1 条 `AUTOEXEC,autoexec_sv.cfg`，之后 **73 张 CSV**。

## 二、卡点的真实形态：两条不同的失败路径

用**整块内存差分**（处理前后各拍一次快照，按 64KB 块比对）实测：

| 正文 | 内存变化 | 表对象 | 结果 |
|---|---|---|---|
| **0 字节** | **0 块** | 无变化 | 不推进 |
| **10222 字节宽表**（40 列、枚举齐全） | **201 块**（堆区大量分配） | **逐字节无变化**，容器仍是自环哨兵 | 不推进 |

⇒ 两条完全不同的路径：

1. **空正文**：`0xA46480`（UTF-8 → UTF-16）转换失败 → 在 `0x5448F4` 直接 bail，
   连一次分配都没有。
2. **非空正文**：`Load` 跑了、逐行迭代了、分配了一堆临时对象 →
   但**第一行都没插进表** → 表仍是空的 → 队列不推进。

第 2 条是关键：**处理确实发生了，只是行被拒。**

## 三、已排除的假设（都带证据，别再重试）

| # | 假设 | 怎么排除的 |
|---|---|---|
| 1 | 列数不对 | 40 列（真实最小 29）也不行 |
| 2 | 列类型/枚举值不对 | 从常量区读出真值 `MAIN`/`NONE`/`CHINA` 填进去，仍不行 |
| 3 | 地区标签过滤 | `0x551DE9` 的 `mov eax,3` 是**无条件**执行的 → 只有 JAPAN 行被跳过，其他值（含 0）都会收 |
| 4 | 文件"不存在"（0 字节）会被跳过 | 0 字节实测同样卡住 |
| 5 | 回复长度有阈值 | 用与 autoexec 完全一致的 10222 字节，仍不行 |
| 6 | 回复没进分派 | 内存差分显示 201 块变化 → **确实在处理**（此条推翻过一次错误结论） |
| 7 | 跨表 ID 查不到就抛 | `0x557FB0` 是**纯 find**，调用方 `0x551E2A` 查不到会走新建分支，不抛 |
| 8 | 插入时抛 | `0x64ABC0` 是 `std::vector::push_back`，正常不抛 |
| 9 | 用 CE 看运行时 | CE 附加后客户端 10~17 秒内 `ExitProcess`（两次复现） |
| 10 | 用 frida 探针看 | 装 7 个内部断点后客户端闪退 |

## 四、已确认的静态事实（下次接着挖的起点）

### 4.1 表类身份

分派代码 `0x544922` 用全局 `0x1169A48` → 对象 → vtable `0x00DF9980`
→ RTTI 反查 = **`CMSMAWeaponSetTable`**。相邻全局：`CBuffTable`、
`CMSMAWeaponEquipCombTable`、`CMSMAColorSetTable`、`CFormationTable`。

### 4.2 调用链

```
0x544922  分派（按 [node+0xC] 的文件序号查 0x544E3C 跳转表）
0x9DC930  CMSMAWeaponSetTable::Load
0xB08960  通用行迭代器（回调返回非 0 就中止）
0x9DC7F0  行回调（首字符 '#' 跳过，否则转 0x551BC0）
0x551BC0  行解析（按列号取字段）
```

### 4.3 列布局（0 基，最小 29 列）

```
0,2        整数
4,5        枚举串（MAIN/EX/SUB1/NONE │ NONE/L_HAND/R_HAND/ACTIVE_WEAPON）
6,7        整数
8,10,11 │ 12,14,15 │ 16,18,19     3 组循环，每组跳 1 列
22         整数
24,25,26,27 整数
28         地区串（ALL/CHINA/JAPAN）
```

枚举常量在 `0xCB8770` 一带（`UNKNOWN/MAIN/EX/SUB1/NONE/L_HAND/R_HAND/ACTIVE_WEAPON`），
`0xCB87D0` 一带还有 `HOMING` / `HACK_CHECK_EX`。

### 4.4 行插入路径（本节之后的部分尚未追完）

```
0x551E01  收行分支
0x557FB0  红黑树 find(键在 [node+0xC])   ← 纯查找，不插入
0x551E41  查不到 → 新建
0x64ABC0  std::vector::push_back，元素步长 0x58（88 字节）= 行结构大小
0x551670  子解析器（内含 0x550700 / 0x550820）   ← 未追
0x551B00  子解析器（内含 0x551900 / 0x551850）   ← 未追
```

**"行被拒"只可能在最后这两个子解析器里**，或某处对空表做了 `idiv` / 取首元素。

## 五、观测工具与两个必须记住的坑

| 工具 | 用途 |
|---|---|
| `server/_build_table_map.py` | 解跳转表 + 运行期读全局 → 出 `表地图.md`（需提权） |
| `server/_extract_columns.py` | capstone 扫解析器抽列号 → 出 `表列布局.md`（纯静态） |
| `server/_dis_parser.py <VA>` | 带列号标注反汇编行解析器（追踪寄存器常量） |
| `server/_diff_snap.py` | **整块内存差分**（处理前后快照比对），当前最有效的仪器 |
| `server/_watch_all.py` | 轮询 69 个表对象（**注意：早期版本因权限 bug 全假阴性**） |
| `tools/ce_tbl_trace.lua` | CE 版断点脚本（**附加会杀客户端，仅留档**） |
| `server/fake_auth.py --reply-delay N` | 回复前先等 N 秒，给外部工具留观测窗口 |

### 坑 1：`VirtualQueryEx` 必须 `0x10 | 0x400`

只给 `VM_READ` 会**静默失败**，返回 0 块 → 快照全是 0 → 得出"什么都没变"的**假阴性**。
这一坑导致过一次完全错误的结论（"回复没进分派"）。

### 坑 2：快照要 1 秒，而两个回复只隔 1 秒

必须用 `--reply-delay 8` 让客户端在请求后干等，才能在"处理前"拍到干净快照。

### 坑 3：CE / frida 都会杀死客户端

CE 附加后 10~17 秒客户端自己 `ExitProcess`（XDt 日志是干净收尾，无崩溃记录）；
frida 装内部断点后直接闪退。**运行时观察只能走"不挂调试器"的内存读写。**

### 坑 4：`run_hooked` 退出后的客户端是孤儿

frida agent 卸载后 hook 悬空，必崩。观察必须让 `run_hooked` 常驻（`--seconds 1800`）。

## 六、如果还要继续，下一步在哪

按性价比排序：

1. **追 `0x551670` / `0x551B00`**（各带 2 个子函数）。目标：找到"行被拒"的那一个判断点。
   成本：逐层反汇编，**按天算**；收益：只解 `msma_weapon_set` 一张表。
2. **拿到任何一份旧服务端的 `settings/` 数据**。哪怕只有几张表，丢进 `fake_auth.py`
   立刻能过这一步，而且大厅里会有真内容。**这是唯一能通向"可玩"的路。**
3. 放弃"内容正确"，转而让客户端跳过这一步（需要改客户端逻辑；
   但 CE/frida 都会被杀，只剩内存补丁，而代码补丁此前被壳做掉过一次）。

**不建议**：继续在"正文内容"上做实验——第 1~5 条已经把这个维度穷尽了。
