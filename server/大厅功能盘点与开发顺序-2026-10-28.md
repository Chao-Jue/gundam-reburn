# 大厅功能盘点与开发顺序

## 已验证基线

用户截图确认进入大厅、打开“进入游戏”菜单。新版探针实测 scene_id=6、mission_ready=1、scene_task_step=5。白屏修复为服务端主动推送 0xDBBC 的 97 字节空协作任务位图。

已验证的是大厅进入和菜单显示，不是机库、商城、匹配或战斗功能。当前界面存在空编队、空排行榜、GP/MB=0、等级显示00等现象；这与服务端大量空数据占位有关，具体字段仍须按当前版本核对。

## 本地资料的实际可用范围

- `refs/msgo-doc/protocol_analysis/INDEX-命令总表.md`：索引声明 564 条下行、351 条上行，共915条，覆盖大厅和战斗，可用于找命令名和操作码候选。当前本地 commands 目录实际只有 E13A 机师列表的4个文件，不能把索引里的 DONE 或详情链接当成本地完整规格。
- `refs/msgo-doc/reverse-login-chain/formats/全链报文总表.md` 及收发 idmap：登录、大厅协议的参考索引。涉及另一版本的长度、地址和流程结论必须重新核对；本次白屏已经证明依赖索引结论猜包会漏掉主动推送。
- `GundamOnline_CHINA_已解密/decrypted/script/UI/`：有大厅、机库、商店、战斗入口等脚本，能辅助理解页面依赖和动画。`L00_MyRoom_01.nut` 使用 MainMenu、Profile、Information，并依赖已有 L00_MyRoom 布局，不能单独当作窗口构造脚本执行。
- `decrypted/settings/`：有 pilot、msma、develop、item、mission、quest、reward、gacha、clan 等目录，但不能默认其内容完整。实测 msma 目录12个CSV均为2字节，msma_settings.csv 内容只有 X；develop 中多数CSV也为2字节。mechanic_overcustom.csv 为162字节，且有历史改动备份，不能当作未经修改的原始表。
- `decrypted/chara/`、`interface/`、`world/`、`sound/`、`scene/` 等：模型、UI、场景和音效资产线索；资源存在不代表服务端已有业务实现，也不证明ID兼容当前客户端。
- 当前启动版本 exe、其解析器/表加载器、运行日志是线格式和字段长度的最终校验依据。原始解密ZIP可作为恢复未改动参考资料的候选来源，先检查目录和对应文件，避免覆盖当前文件。

## 现有服务端

核心仍是 `server/fake_auth.py` 的分阶段协议服务。已保存机师列表在 saved_pilots.json；机师详情、物品初始化、机体初始化、套装、排行榜等大多为空占位。机体初始化目前只发 0x2ACF begin 和 0xFCE6 end，没有非空机体数据。

这意味着后续应建立可持久化的角色资产状态，不能只给每个按钮回一个成功码。机体实例ID、机型ID、武器ID、仓库道具、货币和编队必须彼此一致。

## 建议开发顺序

| 阶段 | 可交付结果 | 核心依赖 |
| --- | --- | --- |
| 1 角色资产基线 | 重登后保留的等级、GP、初始机体与仓库 | 机师详情、有效机型/武器ID、实例ID、持久化 |
| 2 我的机体/机库 | 可见机体、查看武器、修改编队并保存 | 非空机体初始化、武器记录、编队协议与成本规则 |
| 3 大厅基础交互 | 聊天收发、个人资料、基本列表 | 当前版本聊天/资料协议、会话和成员身份 |
| 4 商店与开发 | 买入、扣款、增加资产、开发结果并持久化 | 货币与库存事务、道具和机体表、价格与配方 |
| 5 出击流程 | 可选战场、预约/房间、连接战斗服务 | 可用编队、任务信息、地图、房间和战斗协议 |
| 6 扩展功能 | 好友、邮件、奖励、部队、排行榜 | 对应持久化和业务规则 |

首个建议里程碑：给现有机师一套与其阵营匹配的最小合法初始资产，在“我的机体”显示，能编辑一个出击编队，重登仍保留。暂不把能打开大规模战/局地战菜单视为战斗流程完成。

## 下一轮具体调查

1. 对照 L03_Deck、L03_CharaSelect 等脚本与当前exe，确认非空机体、武器、编队所需字段及实际请求。
2. 查原始解密ZIP中机体/武器表是否完整，区分原始资料、当前占位和生成表；选用当前客户端能解析且资源存在的最小机型集合。
3. 把静态机型定义与角色持有的机体实例分开存储，明确货币和资产的唯一来源。
4. 每条修改业务按“失败复现测试→实现→同测试通过→语法编译→实际客户端功能验证”推进，记录只通过包格式测试还是已实际操作成功。
