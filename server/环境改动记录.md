# 环境改动记录（需要你日后手动回滚）

## 2026-10-14：关闭 hypervisor 启动项

**原因**：《机动战士敢达Online》国服客户端外层是 Themida 壳，它带反虚拟机检查；
本机因为启用了「虚拟机平台 / Hyper-V / VBS」，把自己的 hypervisor 暴露给了用户态
（`CPUID.1:ECX bit31 = 1`），于是 Themida 直接拒绝启动，弹
`Sorry, this application cannot run under a Virtual Machine`。
这是客户端的硬闸，且在保护模块之前触发 —— 不解决它，后面所有工作都到不了游戏画面。

**改了什么**（只改了这一条，功能本身没卸载）：

```bat
:: 管理员 CMD / PowerShell
bcdedit /set hypervisorlaunchtype off
```

实测结果：

| | 改动前 | 改动后 |
|---|---|---|
| `bcdedit` → `hypervisorlaunchtype` | `Auto` | **`Off`** |
| Windows 功能 `VirtualMachinePlatform` | Enabled | Enabled（**未动**） |
| `Microsoft-Windows-Subsystem-Linux` | Disabled | Disabled（本来就没装） |
| VBS 注册表项 | 未显式设置（靠 hypervisor 默认在跑） | 未动 |

**重启后**再确认一次：

```bat
python tools/env_check.py
:: 期望：[OK] CPUID.1:ECX bit31 = 0  且  [OK] 刚开机不久
```

## ⚠️ 坑：关机再开机 ≠ 重启（2026-10-14 实测踩到）

第一次「重启」后复查，环境**完全没变**：

```
CPUID.1:ECX bit31 = 1                 ← hypervisor 还在
连续运行 20 days, 5:32                ← GetTickCount64，根本没重启过
SystemStartOptions = ... HYPERVISORLAUNCHTYPE=AUTO   ← 本次启动实际用的是 AUTO
事件日志：Kernel-Power BootId 始终是 157，没有 6005/6006（事件日志服务没重启）
```

**原因**：`HiberbootEnabled = 1`（快速启动开启）。此时【关机】再按电源键 = 快速启动恢复
—— 系统从 `hiberfil` 还原上次的内核会话，**不重新按 BCD 初始化 hypervisor**，
所以 `hypervisorlaunchtype off` 一点也不生效。它也不会重置 `GetTickCount64`
和 `LastBootUpTime`，这也是为什么事件日志里的 BootId 一直是 157。

**正确做法**（任选其一）：

```bat
:: 管理员
shutdown /r /t 0            :: 真的重启（推荐，最省事）
```

或者先关掉快速启动，之后关机再开机也等于完整启动：

```bat
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Power" /v HiberbootEnabled /t REG_DWORD /d 0 /f
:: 回滚： ... /d 1 /f
```

`tools/fix_hypervisor_off.cmd`（管理员运行）已经把这两件事都做了。
以后判断「有没有真重启」只需看 `python tools/env_check.py` 里那行
**连续运行时长**。

## 什么时候需要回滚

关掉 hypervisor 之后，以下功能会**暂时不可用**，重启并回滚即恢复：

- **WSL2**（含 WSLg、Docker Desktop 的 WSL2 后端）
- **Windows Sandbox**、**Windows Subsystem for Android**
- **VBS / 内存完整性(核心隔离) / Credential Guard**
- 少数要求 VBS 的游戏反作弊新模式

## 怎么回滚

```bat
:: 管理员 CMD / PowerShell
bcdedit /set hypervisorlaunchtype auto
:: 然后重启
```

回滚后 `tools/cpuid_probe.py` 的 `CPUID.1:ECX bit31` 会重新变回 `1` ——
那时候客户端又会开始拒绝启动。也就是说：

> **"能跑游戏" 和 "有 WSL2/Sandbox/VBS" 在这台机器上目前是互斥的。**
> 想玩游戏就 `off` + 重启；想用 WSL2 就 `auto` + 重启。

如果之后找到绕过 Themida 反虚拟机检查的办法（或换成不禁虚拟机的客户端版本），
这一步就可以永久撤掉。

## 顺带记录：另外两处与运行相关的既有设置

1. **兼容性垫片**（不是本次改的，之前就有）：
   `HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers`
   ```
   D:\project\gundam-reburn\launcher\gundam\机动战士敢达Online\GundamOnline\GundamOnline_CHINA.exe  =>  ~ WIN7RTM
   D:\project\gundam-reburn\launcher\敢达启动器\launcher.exe                                       =>  ~ WIN7RTM
   ```
   作用：让进程把 OS 版本当成 Windows 7 上报（运行时因此会加载 `AcLayers.DLL`）。
   如果客户端以后不再需要这个垫片，可以在 exe 属性 → 兼容性里取消勾选。

2. **代码完整性 / 驱动阻止列表**（不是本次改的）：
   `VulnerableDriverBlocklistEnable = 1`，`CodeIntegrityPolicyEnforcementStatus = 2`，
   存在 `C:\Windows\System32\CodeIntegrity\driversipolicy.p7b` 与 `VbsSiPolicy.p7b`。
   这是老驱动 `CPS.sys` 起不来的一个嫌疑因素；关掉 hypervisor 后可能改善，但不保证
   （真不行就继续用 `tools/run_hooked.py` 在 API 边界伪造）。
   **不要**去删这两个策略文件。
