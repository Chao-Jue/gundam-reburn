## 关联链与当前实现

| 层次 | 当前实现/来源 | 尚未证明的内容 |
|---|---|---|
| 持有与装备 | 格纳库资产中的 equipped_weapons；`local_battle.spawn_unit_body`写入三件武器ID、盾ID、特殊装备ID | 当前这一轮战场实收的三个ID是否均非零、与存档一致 |
| 武器定义 | item/item.csv、item/weapon_settings.csv；后者列0为武器ID | 实际运行是否创建对应武器实例 |
| 武器外观 | weapon_settings列2/3/4映射weapon+4/+8/+C，由4E2570按状态选择 | 正确GM变体、挂点、骨骼、收纳/持械姿态及可见性 |
| 动作类别 | weapon_settings列21为类别、列30为基础动作类别；有GUN_SINGLE/WRESTLE/HAND_THROW | 具体动作序列、段数、事件时刻和机体动作映射 |
| 移动 | 机体性能模板、模型参数、本地动作表及控制器 | 加速度、推进与动作切换的实际匹配；当前表仍有大量占位值 |
| 战斗同步 | 已有创建实体、恢复游戏握手 | 连续快照、换武器/攻击状态同步、命中伤害与结算仍未完成 |

服务端负责下发装备ID、配置表和状态；客户端按这些关联加载本地DXG/VRA/MRB、骨骼与材质。不是每次动作都由服务端发送动画文件；本地动画文件存在也不保证状态机选到正确动作。

### ID与文件

- GM：msma_id=777001，model_id=101010101；两者不可混用。
- 基础武器：777101光束喷枪、777102光束军刀、777103手雷。
- 实验外观资源：2010501、4010101、10020101，见 `reference/gm_starter_weapons.json`。只是经本地icon/VRA存在性核对的实验引用，未证明原版GM武器变体匹配。
- `spawn_unit_body`使用175B战斗描述，不能替换为299B格纳库记录。武器槽取 `equipped_weapons`，缺字段时默认为三个0；需要核查实际入参，不能仅检查序列化函数。
- 武器外观路径由4E16C0格式化为 `item/%02d/%04d/attr/EZ_%02d_%04d_%02d.vra`；4E1730以相关资源号构建独立武器动画 `EA_..._%05d.mrb`。
- 当前列3/4复用列2基础外观，是兼容占位；不能据此称拔刀、收刀、变形等状态已还原。
- GM动作表：`chara/01/01/0101/motionlist.csv`，311条启用记录可在公共目录 `chara/01/01/anim/MSA_0101_%05d.mrb` 找到。清单在 `reference/gm_motion_inventory_20261031.json`；不要把未命名动作ID或末列参数猜成攻击时刻。
- weapon_settings列35起字符串模板系列经55BB80/55BD30/55C190处理，支持连续编号展开；用途尚未完整定名，不能直接当motion_id数组填值。
- msma_model仍是32列的实验行，多数值为1，而原生53FA30会读取更后面的列。之前显示故障已说明“能加载模型”不代表该表足够完整。

## 建议接续顺序

1. **只读记录战场基线**：PID、时间、阶段、玩家实体ID、装备槽ID、当前equip_index、武器实例与资源加载结果。先确认真正发给7621的描述和运行客户端一致，区分“没有装备”“未创建实例”“创建了但隐藏/挂载失败”。
2. **追通一把武器外观**：优先光束喷枪，从witem_id查武器定义，跟4E2570的资源选择、VRA加载、模型对象、机体挂点和显示掩码。实际看到正确持枪后，再扩展军刀/手雷及收纳状态。不要整体替换表来试错。
3. **移动表现单独定位**：记录站立、步行、跳跃、推进各状态的实际动作ID与模型变换；对照本地motionlist、移动控制器和性能模板。Wiki的面板速度不提供骨骼、动作映射或完整物理参数。
4. **武器动作**：追踪当前动作类别如何选机体动作和武器动画；核查枪口挂点、射击事件、格斗命中窗、投掷时刻。再处理服务端换武器及攻击请求/通知；不要仅为了让动画播放而直接假设攻击成功。
5. **最后补同步闭环**：对照本客户端实现连续状态更新；目前服务端未实现快照流，不能把本地可动等同于联网战斗完成。

每个Bug先写测试、运行确认因预期原因失败，再修复复跑。原生包读取、资源路径测试与真实渲染分别验收；用户已确认可见的吉姆作为回归基线。
