## 一、已定案（离线反汇编 + 实测双重证据，可直接依赖）

### 1.1 帧层（`0xBD1610`）

```
type = buf[0] >> 4 ;  k = buf[0] & 3
长度字段宽 k+1 字节、小端、**值是载荷长（含 2 字节 opcode）**
本帧总长 = len + k + 2 ；不够就 return 0（不消费）
然后 vt[0x54](buf + k + 2, len)  → 0xAA2D50 on_message
```

`0xE13A` 正文 817 → 载荷 819 → 线上 822 字节，首 5 字节 `01 33 03 3a e1`。
用反汇编字面重写的解码器回读 `op_block()` 输出：817/252/254/2431 四种全部 PASS、剩余 0 字节
（`server/_verify_frames.py`）。**帧层不是问题，别再查。**

### 1.2 正文与记录布局

```
0xE13A 正文(817) = u32 result | 398 eff | 398 zeon | u32×3 | u32 bmg_count | 23n | u8 tutorial
一条记录(398/内存424) = 58 个字段，清单见 server/_field_table.txt
```

58 项逐项相加 = 398，与 `refs/msgo-doc/.../07-*.md §3.3` 的命名表**逐行对齐**
（`avatar` 18B 内部结构也对齐）。字段名：`pilot_id / name[25] UTF-8 / last_in / troops /
level / mil_class / byword / avatar / cmdr_fame / rate_vslocal×3 / 战绩28×u32 / comment[116] /

channel_id / state_bits / accum_point / rank / base_accump / req_accump / level_point /
capture_bonus_state / capture_bonus_limit`。

### 1.3 步骤机（`FUN_0043B530`，10 个 case）——**不需要服务端主动推送**

| step | 地址 | 行为 |
|---|---|---|
| 4 | 0x43B5AD | 离开等待窗（`0x439FB0(game,11,0)` + `0x42EFB0`） |
| 5 | 0x43B5D5 | 等下载器 `[game+0x580]` 变 NULL |
| 6 | 0x43B604 | 四个全局对象收尾 |
| 7 | 0x43B63A | `0x43A680`（显示"机师"进度窗）→ step 8 → 查 `+0x10615` |
| **8** | **0x43B648** | **`cmp byte[game+0x10615],0; je 等待`** ← 客户端卡在这里 |
| 9 | 0x43B660 | 置 `+0x10611=1`，完成 |

**全镜像只有 `FUN_00439190`（`0x4392C0`）把 `+0x10615` 写成 1**（其余写入点 0x43A6B5 /
0x43A828 / 0x43C44F 全写 0）。⇒ 客户端是在等"这条 `0xE13A` 被接受"，没有任何"等推送"的 case。

### 1.4 准入闸门（`0xA93E40`）默认恒放行

`flag[this+0x29e+code]`（默认全 1，全镜像无写 0 的代码）+ 48B 配额块
`this+0x4E0+code*0x30`（计数/上限/周期/时刻，默认全 0 ⇒ 跳过）。`0xE13A` 的 code = `0xC`。

### 1.5 错误上报是"哑"的

- `CGVOProtoLounge + 0x64` = `0x4B31A0` = **空 `ret 8`** ⇒ 解析失败**不打印、不断连**；
- `_proto_lounge + 0x64` = `0xAA29C0`，会拼
  `' _proto_lounge::RecvException(function=' + ',code=' + ') close.....'` 并关连接。

### 1.6 机师外观必须用真值（否则客户端 AV）

外观（`+38..+55` 的 18 字节）全填 0 时，客户端**访问违例崩溃**，
`GundamOnline/user/exrep.log` 会记 `0xc0000005`（格式串在主镜像 `0xDF73A7 = "%d,0x%08x,%s"`，
路径串 `0xDF7348`）。
改用 `decrypted/settings/pilot_form.csv`（7203 行 / 64 个 avatar_id）里的合法值后 **AV 消失**。

`avatar_id=1`（联邦男性1）的合法组合：
`avatar_id=1 gender=0 face=1 skincolor=1 clothes=801 hair=1005 accessory=0 frame=0 voice=1`
（`fake_auth.avatar_wire()` 已实现，从表里读，缺省取 `DEF_*` 行）。

### 1.7 两个格式约定（别再记错）

- **`troops` 线上是 0 基：0 = 秩序/eff，1 = 抵抗/zeon**（参考文档 §3.11 规则③；
  §3.3 命名表里的"1=联邦/2=吉翁"是内部口径）。
- 所有 `_r` 应答必须**定长**，不要放变长（NUL 串）字段，否则游标错位、整条被丢。

## 三、★ `--pilot-hook` 一直在劫持 0xE13A 的解析路径（已移除）

客户端 `0x70E9` 自检里明确报过：

```
Addr:ACFE76, C:E895A4F8FF, O:E9892F0503
```

`0xACFE76` 正是 `0xE13A` 分支里**读 `result` 的 `call a5a310`**，`O:` 是被改成 jmp。
而 `start_local.cmd` 一直带 `--pilot-hook`。⇒ **今天大部分机师实验都是在被劫持的路径上做的。**
已移除该参数，并给 `tools/pilot_hook.js` 加了"⛔ 已停用"横幅。

## 四、⛔ 运行时观测这条路已封闭（两次实证）

| 手段 | 后果 |
|---|---|
| inline hook（`pilot_hook.js`，改代码字节） | CPS 报 `Addr:ACFE76 ...` 代码篡改 |
| **vtable 数据补丁**（`vt_probe.py`，只改 4 字节数据） | **客户端立刻闪退**（用户实证；`restore` 失败，会话被销毁） |

⇒ **结论：不要再对客户端做任何注入/补丁。** 后续所有实验必须走"只改服务端"的黑盒路线。

## 五、当前唯一未解的问题

**`0xE13A` 到底有没有进到 `0xAA2D50`（on_message）？如果进了，在哪一步失败？**

静态侧能做的已经做完：
- 帧 ✔、长度 ✔（含 24 个长度的实测）、布局 ✔、闸门 ✔、步骤机 ✔；
- 失败出口 `0xACFE82 / 0xAD0044 / 0xAD0085` 都会调 `vt[0x64]`，而它是空 `ret 8` ⇒ 无声。

**剩下的离线抓手（不需要客户端）**：
1. **9 个候选 vtable 的 `+0x54` 静态比对** —— 确认"真正接收 lounge 报文的对象"是哪个类。
   已知：`0xBD1610`（分帧）出现在 9 个类的 `+0x20`：
   `CGVOProtoLounge(0xE14D04)/_proto_lounge(0xE09A74)/CGVOProtoAuth/CGVOProtoBattle/
   _proto_auth/_proto_battle/Codec@vce/iProxyListener@ivce/CGVOProtoBattleReplaywar`。
   其中只有 `CGVOProtoLounge+0x54 = 0xAA2D50`（真分发器），`_proto_lounge+0x54 = 0xA93EC0`
   （只报 error(0x242,0) 的空实现）。**需要确认运行时实例化的是哪个**（靠构造函数链静态推）。
2. **重新数 0xE13A 分支的消费量**：我按"`a5a270/a93f50` 只动输出缓冲"算出 817，
   但 `a5a270` 里确实是 `[ecx] += 4` —— 要确认它拿到的 `ecx` 是**输出缓冲指针**不是**报文游标**。
   这一条如果搞错，真实长度就不是 817（虽然 813~905 都试过了，但步长 4 可能漏掉 818~820 这类奇数）。

**服务端侧还能试的**（零风险）：
3. 用步长 1 再扫一次 810~825（覆盖奇数长度）；
4. 让 65 张表带**真实内容**（现在全是 2 字节 `X`）—— 如果机师路径要查表，这是唯一还能动的变量；
5. 换 opcode 邻居再试一轮。

## 六、给下一次开工的三句话

1. **不要再想"推送"**：步骤机没有等推送的 case，等的是 `+0x10615`，只有 `0xE13A` 成功回调会置它。
2. **不要再碰客户端**：inline hook 会被 CPS 抓到，vtable 数据补丁会让它闪退。
3. **数据要真**：外观字段必须来自 `pilot_form.csv`（否则 AV）；`troops` 线上 0 基；
   定长、UTF-8、无 NUL。布局与字段名已全部定案，见 §1.2。
