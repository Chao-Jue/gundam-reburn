## 怎么继续（以 `msma_weapon_set.csv` 为例）

1. `Load`（`009DC930`）先 `call 009DC860`，再调通用行迭代器 `0xB08960(text, 2, 回调, this, g, 3)`。
2. 行回调 `009DC7F0` 只做两件事：首字符是 `#` 就跳过；否则 `call 0x551BC0` 解析这一行。
3. `0x551BC0` 是**该表的行解析器**，里面用 `0xB081E0(row, 列号)` 取整数字段、
   `0xB082E0(row, 列号, &wstr)` 取字符串字段，列号是**写死的常量**：
   `0, 2, 4, 5, 6, 7` → `8..19`（3 组） → `22..28` → 再分派到子解析器
   `0x551670` / `0x551B00` / `0x551F00`。
4. 子解析器里还会拿 ID 去别的表查（跨表引用），所以列值不能乱填——
   **这是"逐列试"不收敛的根本原因**。

下一张表照这个套路：`Load` → 找 `0xB08960` 的回调 → 反汇编回调 → 记录所有
`0xB081E0/0xB082E0` 的列号 → 得到列布局。

## 行解析器长什么样（以 `CBuffTable` 为例）

`CBuffTable` 的 vtable 第 0 槽 = `0053EF50`，反汇编开头就是：

```asm
0x53EF7D  push 0            ; 列号 0
0x53EF7E  push edi          ; row
0x53EF7F  call 0xB081E0     ; 取整数
0x53EF8B  mov  [esi], eax   ; row+0
0x53EF88  push 1            ; 列号 1
0x53EF8D  call 0xB081E0
0x53EF95  mov  [esi+4], eax ; row+4
0x53EF98  push 2            ; 列号 2 → 取 wstring（call 0x4559C0）
```

**结论：行解析器就是"push 列号 → call 0xB081E0/0xB082E0 → 存字段"的直线代码**，
列号是立即数，列布局可以直接数出来。这一张表就是 3 列。

⚠️ 注意：不同基类的 vtable 布局不同——`CMSMAWeaponSetTable` 的第 0 槽是 `Load`
（它调迭代器），行解析器是迭代器回调 `009DC7F0` → 真正解析在 `0x551BC0`；
而 `CBuffTable` 这类第 0 槽直接就是行解析器。**所以每张表都要先判断这一槽是 Load
还是 ParseRow**：看开头有没有 `call 0xB08960`（有=Load，没有=ParseRow）。

## 下一步（机械工作，可以批量做）

对 68 个地址逐个：
1. 反汇编首 0x200 字节；
2. 若含 `call 0xB08960` → 取它前面的回调 `push imm32`，那才是行解析器；
3. 在行解析器里收集所有 `push <列号>; call 0xB081E0|0xB082E0` 的列号；
4. 最大列号 +1 = 这张表的列数，同时得到每列是**整数**还是**字符串**；
5. 若出现 `call 0x551xxx` 之类的子解析器，说明这行有**重复段**（武器槽/模块槽），要再进一层。
