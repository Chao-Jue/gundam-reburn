## 4. 已经排除的原因

这些都改过或核对过，白屏没有变化。不要再沿这些方向改包。

1. **还缺一条大厅请求。** 步骤已经到 `0x14`，之后只有 `0xD377`。
2. **`0x6B74` 是没应答的业务包。** 它是客户端错误上报。17:45:50 的 `user\exrep.log` 是白屏期间另一次被捕获的访问异常（异常地址 `0x07468D71`，读 `0x4285074`），不是最初进白屏的原因。
3. **频道记录 type 决定场景。** 记录已改成解析器 `0xA94CE0` 要求的 54 字节，type 放在偏移 41，当前发的是 4。客户端接受了列表并选择频道 1，但 `0xC475` 的目的地仍是 0。`server/fake_auth.py` 里 `channel_entry()` 的注释还写着「type 会被当成场景编号」，这句已经被这次运行否定。
4. **教程步骤是 0 所以卡在新手关。** `0x063E` 正文偏移 12 现为 1（`END`）。探针 `tuto=1`，确认写进了 `game+0x105E8`。画面不变。`pilot_select_body()` 里「0 会进入新手教程所以白屏」这句注释同样过时。
5. **回归标志必须非 0 才会开大厅。** 那是旧文档对另一条路径的说法，而且后来被文档自己改成「那是登录战斗服」。本客户端见第 5.2 节：标志为 0 时步骤机正常收尾；为 2 时才会去建下一个连接对象。
6. **`0x1D02` / `0xA64A` 回调没执行。** 早期探针把反编译器的 uint 下标当成了字节偏移。正确偏移是 `proto+0x1670` 和 `proto+0x16A0`。修正后的日志里两个计数都会涨。修正前的 `cnt_1d02=0`、`cnt_a64a=0` 不能用。

## 5. 当前客户端上坐实的代码

### 5.1 场景函数把编号清掉了

`0x433A80`，`ecx` 是游戏对象，唯一会发 `0xC475` 的地方（`0x433B76` → `0xA566E0`）。

- `game+4 == 0`：用调用者压入的场景编号。
- `game+4 != 0`：函数先压入两个参数，再把此时的 `[esp+0x44]` 写成 0，然后用这个 0 做场景编号。调用者传入的编号不参与后面的目的地选择。

目的地映射在 `0x433BB8`，下标是 `场景号 - 4`，只覆盖场景 4 到 19：

| 场景 | 目的地 |
| --- | --- |
| 4 | 1 |
| 6 | 3 |
| 8 | 2 |
| 13 | 不发送 |
| 17 | 4 |
| 19 | 5 |
| 其余，含 0 | 0 |

脚本注册处 `0x59CACE`：`GSCENE_MAIN_MENU = 6`。场景 6 本来会发目的地 3。
实际每次 `0xC475` 都是目的地 0，因为 `game+4` 从启动起就非空。

发包之后调用 `0x52B950`。这个函数是 `xor al, al; ret 4`，不加载地图，也不创建窗口。
所以 `GameState.changeScene` 本身不会把主菜单或个人房间建出来。

### 5.2 大厅最后一步没有创建界面

`0x43AB36` 读 `game+0x105A0`：

- 等于 0：把步骤写成 `0x14`，直接返回。
- 等于 2：把步骤写成 `0x14`，再调用 `0x4421E0`。
- 其他非 0：调用 `0x43F100`。

`0x4421E0` 用 `game+0x10920`、`+0x109A1`、`+0x109CC`、`+0x107B8`、`+0x3A9C4` 填一个 0xCC 字节的对象，再交给 `0x43DB10`。这是下一次连接，不是打开菜单。当前回归标志是 0，这条不会走。

紧接着的 `0x43AB6F` 去掉阻挡 `0x0D`（字符串表 60,29,13，「正在变更频道」）并清掉 `game+0x544` 的任务。探针看到的就是这个收尾。

### 5.3 主菜单和个人房间是另外两个对象

主菜单场景：

- 类 `CMainMenuScene`，虚表 `0xDFA070`，构造 `0x9EA0A0`。
- 场景工厂 `CGameSceneMgr::` 虚表 `0xDF8334`，槽 `+0x44` 是 `0x9E2750`。
- `0x9E2750` 用 `参数 - 1` 做下标。下标 5，也就是场景号 6，创建 `CMainMenuScene`。
- 这个函数没有直接 `call`。唯一指针在虚表 `0xDF8378`。谁在进频道之后调用这槽，还没找到。

个人房间窗口：

- 类 `CMyRoomWindow`，虚表 `0xD6AC4C`，构造 `0x824840`。
- 窗口工厂 `0x6CFF50`：参数减 1 后的下标 4（参数 5）分配 0x170 字节并调用该构造，存到对象 `+0x1E8`。
- 读取函数 `0x6D0480` 在对应槽为空时才调用工厂。
- `0x82A040` 是 `CMyRoomWindow` 虚表槽 `+0x28C`。它向游戏对象注册场景 `0x12` 的回调 `0x8248E0`，然后用虚函数加载宽字符串 `L00_MyRoom`（`0xD2D5CC`）。
- `0x8248E0` 只有参数等于 `0x12` 才跳到 `0x822A30`。
- 这次运行没有证据表明 `CMyRoomWindow` 被创建，也没有证据表明场景 `0x12` 的回调被挂上。

`0x8EA440` 是另一个窗口（`CInventoryMenuWindow`）的同一虚表槽。它在某个虚函数返回 0 时调用 `changeScene(6)`。那是进入背包一类界面时的路径，不是频道登录的收尾。

### 5.4 服务端推的脚本建不出房间

`0xA64A` 的 `src` 按字符串表 `10,10,126` 格式化成 `./script/%s`。
当前推的是包内已有的 `test_lobby_scr_0.nut`，正文是文件名加两个 0。该文件只打 trace。
`cnt_a64a=1` 只说明文件被执行过，不说明它创建了界面。

`script/system/game_event.nut` 在载入时不切场景。`onGameStateEvent` 先关禁用窗；教程步骤已是 `END` 时，没有分支去打开主菜单。
`script/UI/L00_MyRoom_01.nut` 假定 `L00_MyRoom` 布局已经存在，不能靠 `0xA64A` 直接当成窗口构造函数来跑。

## 7. 还没找到的入口

白屏的直接原因已经清楚：等待窗关闭后，没有人创建 `CMainMenuScene` 或 `CMyRoomWindow`。

还要查的是：进频道之后，哪一段代码以场景号 6 调用 `CGameSceneMgr` 虚表 `+0x44`（`0x9E2750`）。
`0x433A80` 不是这段代码。它只发目的地 0，再调用空函数。

已看到、但还没串完的点：

- `0x82A040` 会注册场景 `0x12` 并加载 `L00_MyRoom`，但它是 `CMyRoomWindow` 自己的方法，窗口得先被工厂造出来。
- `0x43ACE0` 把场景回调放进 `game+0x105C8` 起的列表，并且只在编号等于 `game+0x105D0` 时入队。`0x105D0` 在相邻函数里也是这个 vector 的尾指针，不能把它当成「当前场景号」来读。
- 场景回调分发 `0x436090` 只有一处调用，在 `0x436161`。这次没有追它的触发条件。
- 宽字符 `changeScene` 的引用搜索被中断，没有结果。

在找到这个调用点之前，不要再改教程步骤、频道 type、回归标志，也不要换一个不会创建窗口的脚本碰运气。
