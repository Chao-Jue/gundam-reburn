## 1. 已定案（可以直接依赖）

### 1.1 `0xE13A` 正文结构 = 817 字节

```
u32 result
398 pilots_eff      ← 固定 1 条，**没有 count 前缀**
398 pilots_zeon     ← 固定 1 条
u32 del_remain_sec_eff
u32 del_remain_sec_zeon
u32 charge_point
u32 bmgpack_count (<= 0x10)
23n bmgpack_list
u8  is_tutorial_end   ← 读完必须 cur == end
```

证据：
- 分支入口 `0xACFE1F`：`push 0x4E5` → `vt[0x78]` 分配 **1253**
- `1253 = 4 + 424 + 424 + 4×3 + 4 + 0x10×24 + 1`（**逐项精确相等**）
- 两处 `cmp edi,1; jb` 证明每侧**硬编码只读 1 条**
- 唯一成功判据：`0xAD007D cmp cur,[end]; je 0xAD009C`

### 1.2 机师记录 = 398 字节线长 / 424 字节内存

逐项相加 `FUN_00a956f0`（`0xA956F0..0xA95C33`）：

```
4(id) + 25(name) + 4 + 1+1+1 + 2 + 18(avatar)   = 56
+ 4 + 2+2+2                                      = 66
+ 28×4                                           = 178
+ 116                                            = 294
+ 4 + 31 + 1+1+1                                  = 332
+ 4 + 4 + 31 + 1+1                                = 373
+ 4+4+4+4+4 + 1 + 4                               = 398
```

- 原语宽度：`a5a310`=4B、`a5a330`=2B、`a5a360`=1B、`a5de30`(avatar)=18B
- `a5a270`/`a93f50`/`a94330`/`a5d400` **只动结果缓冲区指针，不吃报文流**
- 字段偏移：`+0x00 id / +0x04 name[25] / +0x20 last_in / +0x24 troops / +0x25 level /
  +0x26 mil_class / +0x28 byword / +0x2C avatar(22) / +0x44 cmdr_fame / +0x48,4a,4c u16×3 /
  +0x50..0xBC 28×u32 / +0xC0 [116] / +0x134 u32 / +0x138 [31] / +0x157,158,159 u8 /
  +0x15C,160 u32 / +0x164 [31] / +0x183,184 u8 / +0x188..0x198 5×u32 / +0x19C u8 / +0x1A0 u32`

### 1.3 步骤机与两个标志

| 地址 | 语义 | 证据 |
|---|---|---|
| `game+0x10615` | 状态机前进标志（byte） | `0x4392BE` 写 1；`0x43B64D cmp` |
| `game+0x10611` | **"忙"标志**（byte） | `0x42DA40 cmp byte[ecx+0x10611],0 / call 0xa4f430 / mov eax,1` |
| `game+0x10619` | `(bmg列表 != 0)` | `0x4392B6 mov [ebx+0x10619], cl` |
| `game+0x1061C` | UI/进度管理器指针（**非 0**，实测 `0x2487ada0`） | `0x439FE2 cmp dword[esi+0x1061C],0` |
| `game+0x580` | **下载器指针**（表阶段同款），非 0 就等待 | `0x43B5DB cmp dword[ecx+0x580],0` |

### 1.4 两个关键函数

| 地址 | 真实作用 |
|---|---|
| `0x439190` = `FUN_00439190` | **`0xE13A` 成功回调**（vt[0x80]，thunk 在 `0xAF6170`，`ret 0x24` = 9 参数）。填数据、刷新卡片、置 `+0x10615/10619/1061A`、`call FUN_00438b30(5)` |
| `0x43A680` | ⚠️ **"进入等待"**：处理 `game+0x10A68`/`+0x10BF0` 两张卡 → `0x439FB0(game, 5, 1.0f)` 显示进度窗 → `mov byte[game+0x10615], 0` |
| `0x43B5AD` | **"离开等待"**：`0x439FB0(game, 11, 0.0f)` + `0x42EFB0(game)` + 步号+1 |
| `0x439FB0(this, int 阶段ID, float 值)` | 设置进度窗的**阶段+进度**（**不是显隐开关**）。`(5,1.0)`=机师阶段，`(11,0.0)`=通用数据阶段 |

## 2. 今天试过且失败的路（别再重复）

| 尝试 | 结果 |
|---|---|
| 扫长度 1~1300（含 817/845/10200 等） | 全部无进展 |
| `kind=1/2/3/4` 各种长度字段宽度 | `clientBody` 全 49（或 510），无一次成功 |
| `poke [game+0x10615]=1` | ✅ **界面真的切到「选择机师 / PILOT SELECT」**，但模态窗"正在取得机师数据"没关、按钮点不动 |
| `poke [game+0x10611]=0`（清"忙"） | 无变化 |
| `call 0x43A680(game)` | ❌ 反而是**"进入等待"**：已在登录界面的游戏上又弹出了进度窗（用户观察） |
| `call 0x439FB0(game,11,0.0f)+0x42EFB0(game)` | 无变化（只把文案从"正在取得机师数据"变成"正在取得数据"） |
| `call 0x439FB0(game,5,0.0f)` | 无变化 |
| `清空 [game+0x10624] 任务列表` | 列表本来就是空的（`end==cap`），与窗无关 |
| `call FUN_00439190(game,0,eff,zeon,0,0,0,0,0,0)` | ❌ `access violation accessing 0x0`（某参数被当指针解引用） |

**结论**：这个模态窗只能由成功回调关，poke 标志 / 调进度函数都无效。

## 3. 下一步（按优先级）

1. **把 `FUN_00439190` 的 9 个参数语义逐个定案**（纯静态，不需要开客户端）。
   已知 `[esp+0x100]`（=P7）是 bmg 列表、`0x4392DB mov ebp,[esp+0x14]`（=P5）之后直接
   `[ebp+0x3e]` ⇒ **至少有一个我当"数值"传的参数其实是记录指针**。
   把 146 行整理成「参数 → 用途」表后，再调一次就不会崩。
2. 若 2 能过，模态窗应自动关闭，两张卡片出现机师；接着走 `0xF705 → 0x063E`（规格本机可反编译）。
3. 帧层"大于 255 怎么封装"仍未定。**注意**：`clientBody` 读数不稳定（同一帧 49 / 510 都出现过），
   基于它的一切结论都不可信，要重新做观测。

## 4. 铁律（踩过的坑）

1. **msgo-doc 只能当思路，不能当证据**（别的 build）。
2. **绝不在 `0xAA2D50` / `0xAA2DA4` 上挂 inline hook** —— CPS 会读那段机器码做校验，
   实测 `0x70E9` 报告出现过 `Addr:AA2D50, C:558BEC83E4, O:E9AF00D302`，随后客户端卡死。
3. **只改 `NativeFunction` 调用、不改指令字节时 CPS 不报警**（已验证多轮）。
4. `start_local.cmd` 发现 30000 已监听会**复用旧 fake_auth**（参数改了也不生效），
   已改成先 taskkill 再启动。
5. 客户端某些阶段会**静默 30~60 秒**（如 0x70E9 自检），别当成卡死。
6. 那个进度模态窗**在登录界面也能被拉出来**，脏状态下的界面判断不可信，先重启。
