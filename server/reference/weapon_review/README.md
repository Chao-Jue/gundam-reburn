# 武器复核数据集

`weapon_review.json` 是「武器数据 → 模型 / 图标 / 特效」的唯一事实来源，由
`tools/weapon_review.py` 从 Wiki 缓存 + 客户端资源装配。当前进度：**L1 图标层**。

```powershell
# 重新装配骨架（约 5 秒；会把所有边清空重来，慎用）
python tools/weapon_review.py --build --port 0

# L1：为每个图标组生成客户端图标候选（可重复跑，已下过的图不重下）
python tools/weapon_review.py --icons --port 0

# 导入国服武器对照表（GBK CSV）：写 client_id / 模型 / 图标，见下节
python tools/weapon_review.py --import-csv "国服武器对照_对照表.csv" --port 0

# 打开复核台
python tools/weapon_review.py --port 8770 --open
```

## 结构（详见 `schemas/weapon_review.schema.json`）

- `models[key]`：客户端事实（dxg 路径、资源号、网格名、挂点、DXG 版本），**不带武器族**，
  允许一个模型被多个武器族共用。
- `icon_pairs[key]`：`hangar`（格纳库图标）+ `battle`（战场内图标）+ 两组候选
  （`candidates` / `battle_candidates`）。键来自 Wiki 图片名称。
- `effect_groups[key]`：`mode` = `normal` / `alt`，`slots` 五个槽位。**尚未开始**。
- `weapon_data[key]`：主键行，`model` / `icon_pair` / `effect_groups` 都是可空的引用。
- `review_log`：追加式审计，每次采纳都会留一条。

三条硬规则：

1. 一条武器数据最多两组特效，`mode` 不得重复。
2. 人工 `confirmed` 的边不得被批量/自动流程覆盖（`--icons` 会跳过已确认组）。
3. 图标候选只写进 `candidates`；只有人工采纳才写 `hangar`/`battle`。

## L1 图标层（已实现）

- 候选复用 `weapon_icon_match` 的归一化 + 描述子（颜色 .45 / 边缘 .35 / alpha .2 的加权 MAE），
  对 `interface/icon/item/s/*.dds`（5192 张）排序取前 6。
- **战图标必须独立匹配**：仓图标 5192 张、战图标只有 1023 张，且按武器类型编号（b01/b02/b03），
  按同号配对只命中 **83/5192**。所以 `battle` 允许为空，候选单独列一组（前 4 个）。
- 采纳一组图标 → 写回 `icon_pairs.hangar/battle`、状态置 `confirmed`，
  并把从图标文件名反推的模型（`s02010601 → 02010601`）传播给该组所有 `weapon_data` 行。
  一次决策平均覆盖 5.7 行，最高 149 行。

**当前进度（2026-11-04）**：1028 个图标组里 **240 组已有候选**，其余 788 组缺 Wiki 图片。
不是逻辑问题——`wiki.biligame.com` 在批量抓图后开始返回 **HTTP 567**（整站限流，换 UA 无效），
已下 240 张。限流解除后重跑 `--icons` 即可补齐：脚本只对没下过的图查 URL，下过的直接跳过。

## 国服武器对照表导入（外部数据）

外部给的 `国服武器对照_对照表.csv`（GBK，13814 行）以 `(国服页名, 行序)` 能对上本数据集 **5848 行**，
且武装名 5848/5848 完全一致。`客户端号` 主要索引图标（1395 个去重号里 1132 个能对上
`s<号>.dds`），其中 761 个同时是模型号——**所以它不能反过来当模型号用**。

导入后（2026-11-05）：

| 项 | 结果 |
|---|---|
| 写入 `client_id` | 5809 行（其余 39 行是「待定」无号） |
| 同时确定 `model` | 3439 行 |
| 图标组组内号唯一 → 写图标并确认 | 747 组 |
| 组内多号冲突 | 0 组（发生时会记 `conflict`，不猜） |
| 未匹配 | 7966 行 / 249 个页名 |

`evidence.source = 'import'`，与人工采纳的 `manual` 分开；`--icons` 不会覆盖已确认组。

未匹配的 249 个页名里 **240 个正是「空武器表」的机体**，带 7966 行武器名 + 客户端号，
但没有 Wiki 属性（威力/弹数）。是否把它们物化成 `csv_only` 行还没定——见设计文档第 10 节。

## 页面上现在能做什么

- 按机体 / 按图标组 / 按模型 / 清单 / 缺口 五个视图。
- **按图标组**是 L1 复核台：左侧 Wiki 图标、中间 6 个仓图标候选 + 4 个战图标候选（默认预选第一个）、
  下方「受影响的 N 行」；点「采纳选中」写盘并刷新进度。
- 每行的三个状态点 = 模型 / 图标 / 特效，全灰表示未定。
- 缺口视图列出无图片名称的 3297 行、解析失败的 131 个模型、空武器表的 389 个机体。
