# 机体级汇总导出

由 `python tools/unit_export.py` 生成，把四处已有结果按**机体页**归并到一张表里：

| 来源 | 提供什么 |
|---|---|
| `server/reference/wiki/units.json` | 机体页名、revision、武器行与属性 |
| `server/reference/wiki/unit_images.json` | 机体立绘 URL |
| `server/reference/model_matches.json` | 人工确认的 MSM 机体模型 |
| `server/reference/weapon_review/weapon_review.json` | 武器行 → 客户端号 / 武器模型 / 两套图标 |

## 文件

- `units.json`：按机体嵌套，`weapons[]` 里是这一机体的所有武器（含客户端号、模型、图标）。
- `units.csv`：一行一条武器，机体字段（页名/立绘/MSM 模型）重复展开，Excel 直接看。6244 行
  = 5855 条武器 + 389 个没有武器表的机体各占一行。
- `unit_index.csv`：一行一个机体，带各层计数，适合看进度和筛缺口。
- `completeness.json`：覆盖率 + 缺口清单（没有 MSM 模型的机体、没有模型的武器行等）。

`units.json` / `units.csv` 里 **null / 空字符串表示尚未确定，不是 0**。图标只搬「已确认」的组。

## 当前完整度（2026-11-05）

| 层 | 有 | 总数 | 覆盖率 | 说明 |
|---|---:|---:|---:|---|
| 机体立绘 | 696 | 751 | 92.7% | 只有 URL，未下载 |
| **机体 MSM 模型** | **80** | **751** | **10.7%** | 最大缺口，见下 |
| 武器客户端号 | 5809 | 5855 | 99.2% | 来自国服对照表 |
| 武器模型 | 3439 | 5855 | 58.7% | **已到上限**，见下 |
| 武器图标 | 5002 | 5855 | 85.4% | **已到上限** |

### 为什么「武器模型」只有 58.7%，而且是上限

客户端号主要索引图标，只有约一半同时就是模型号。5809 行里：
- 3439 行的号在 `models` 里 → 已全部写入
- 803 行的号既不是模型号、也没有图标文件（多为 9/10/12 位号，本端没有对应资源）
- 其余是「号有图标但不对应模型」

要再提高只能靠**图像/几何匹配**（`weapon_threeway` 那条路）从图标反推模型，不能靠号直接得到。

### 为什么「武器图标」能到 85.4%

`--fill-icons` 按客户端号直读 `s<号>.dds`：文件存在就填，不存在就留空。
这一步不是猜测——剩下 853 行就是真的没有图标文件（或没有客户端号）。

### 最大的缺口：机体 MSM 模型只覆盖 80/751

`model_matches.json` 里只有 87 条人工确认记录，对应 80 个机体页。要补这一层，
只能走 `tools/model_matcher`（人工看图匹配），或先用 wiki 的机体名去对
`local_model_names.json`（68 个日文名）做候选，再人工确认。**这一步没有做过。**
