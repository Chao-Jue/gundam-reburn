- 最后一条恒为 `develop/mechanic_overcustom.csv`；
- 与 `download_list.csv` 的 74 行做差集，**客户端从没要过的 9 张**是：

⇒ **"缺表"这个方向对"能否进大厅"是无关的**。客户端只要 65 张，65 张全给完了。
⇒ 65 张之后客户端不再要第 66 张，不是卡在下载，是**下载阶段已经结束**。

> 注意顺序也不是 CSV 顺序：客户端第 7 条要 `item/bullet.csv`，而 CSV 第 7 行是
> `item/item.csv`。所以客户端用的是自己内嵌的清单，跟我们的 CSV 只是同集合。

## 2. 65 张之后客户端只做一件事：发 `0x70E9`

```
15:51:50  第 65 张 develop/mechanic_overcustom.csv 请求 → 我们回 op_5290
15:51:53  客户端 frame 68（明文 58 字节）
          消息 操作码=70e9 载荷=56 余=05000000000000000000000000
                43 3a 5c 57 49 4e 44 4f 57 53 5c 73 79 73 74 65 6d 33 32 5c
                75 78 74 68 65 6d 65 2e 64 6c 6c 5f 61 30 61 65 32 62 32 62 00
          = 三个整数 (5, 0, 0) + 路径 "C:\WINDOWS\system32\uxtheme.dll_a0ae2b2b"
15:52:38  recv timeout (45s idle)   ← 我们一帧都没回
```

另一轮（14:13）里同一条出现过两次，间隔 36s，第二次是 `MSCTF.dll_36bd5c96`。

**判读**：这是反外挂的**模块完整性上报**——客户端把某个 DLL 连同一个 8 位十六进制
指纹（很可能是它自己算出的哈希）报给服务端，然后**等服务端裁决**。
我们从不回复，所以它就一直等。

## 3. 已加到服务端的能力

`server/fake_auth.py` 新增：

| 项 | 说明 |
|---|---|
| `parse_msg(pt)` | 通用入站解析，返回 `(opcode, 正文)`，不再只认 `0xF86A` |
| `op_block(opcode, body)` | 任意操作码的下行消息构造（自动 16 字节对齐） |
| `body_70e9(rest, mode)` | 四种应答候选 |
| `--seventye9 / --70e9` | `none` / `zero`（默认）/ `ok4` / `mirror` / `echo` |

四种候选的正文：

| mode | 正文 | 理由 |
|---|---|---|
| `none` | 不回 | 现状，用于对照 |
| `zero` | 12 个 0（3 个整数） | 最像"校验通过"的 ack |
| `ok4` | 4 个 0（1 个整数） | 有些协议只要一个 result |
| `mirror` | 回显请求前 12 字节（5,0,0） | 如果客户端把第一个整数当"请求类型"回读 |
| `echo` | 整段回显 | 兜底 |

自测已过（构造/解析/对齐都正确，见 `op_block(0x70E9, 4 个 0)` → `0006e97000000000 0006ffff00000000`）。

## 4. 本轮实验步骤

1. **先手起 fake_auth**（不要让它被 `start_local.cmd` 顶掉，30000 已占用时 start_local 会跳过）：
   ```
   python server/fake_auth.py --sweep --sweep-gap 2 --idle 60 --seventye9 zero
   ```
2. 用 `tools/start_local.cmd`（右键管理员）起客户端，点登录。
3. 观察 `server/fake_auth.log`：
   - 出现 `[70e9] 收到模块校验报告（56 字节）→ 回 op_70e9 12 字节正文（zero，n=..）`
   - **关键判据**：之后客户端有没有新动作
     - 界面推进 / 出现新状态窗口 → **成功，0x70E9 就是最后一道门**
     - 又发来新的 `0x70E9`（另一个 DLL）→ 说明它一批一批地报，继续回就行
     - 还是静默 → 换 `--seventye9 ok4`，再不行 `mirror` / `echo`

## 5. 如果四种都不行

那时说明客户端不是在等"裁决"，而是在等一个**带具体结构**的回复（比如校验通过令牌）。
下一步就去镜像里找 `0x70E9` 的下行处理函数：主代码段是明文，
但**反外挂相关代码很可能在 `.vmp0`（231KB）里** —— 那就得换思路，
比如直接让 65 张之后的那个状态推进（用服务端多发一条 `0xA5DA`/休息室消息试试）。
