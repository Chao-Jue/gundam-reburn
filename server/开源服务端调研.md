# 开源 / 泄露服务端调研报告

> 调研对象：《机动战士敢达Online》(MSGO, 機動戦士ガンダムオンライン, 国服久游代理)
> 目的：评估"是否已有公开的开源服务端/模拟器可以直接拿来用"，避免重复造轮子
> 时间：2026-10-14 · 方式：**只检索公开资料，未下载任何文件、未运行任何服务端** · 仅评估

---

## 0. 一句话结论

**没有。** 到目前为止，公开互联网上**不存在** MSGO(PC, 2012–2022) 的
开源服务端 / 模拟器 / 协议实现。有几点补充：

- 社群目前主要是"**解包素材 + 换引擎(UE5)重制**"的路线，**不是协议级模拟**；
- 有几款**别的**高达网游有成熟的开源端（SDGO / UCGO / GDXSV），
  可以作为**架构与方法论参考**，但协议完全不同，**不能直接复用**。

> ### ⚠️ 勘误（2026-10-15）
> 本报告初版把贴吧精华帖「机动战士敢达OL私服预热活动正式开启!」当作**真私服**的证据。
> 经用户核实：**该帖实为愚人节玩家自发的纪念活动，并非真实私服**。
> 因此"国服有民间私服在运行""端在小圈子内流转"等推论**全部不成立**，已从结论中删除。
> 目前的正确认知是：**没有任何可靠的私服/服务端泄露线索**。

### 2.2 百度贴吧 —— 只有线索，但**已被证伪**（勘误）

「机动战士敢达OL吧」目前仍在活跃（2026 年），相关帖子：

- 📌 精华帖：「机动战士敢达OL私服预热活动正式开启!」（122 条回复）
  → ❌ **勘误：经用户核实，这只是愚人节的玩家纪念活动，不是真私服。**
- 「这么多年了，就没有大佬破解做单机版的吗」
- 吧友表示：旧硬盘里保留了 **国服 9.0.0.235 端**，想试着搞单机
- 有人在**征集日服客户端**做素材，称"解包文件未来酌情释出部分内容"
- 有人用 AI 把机体模型**转译进 UE5**，尝试先做 **10v10 单机版**

**从这些帖子能读出的关键事实（已剔除私服误判）：**

1. **是否存在私服：无证据。** 之前当作证据的精华帖已证伪，故**不可据此认为私服存在**。
2. 社群主流技术路线是 **解包素材 → UE5 重制**，而不是"模拟原协议让原客户端连上"。
   → 这条路径客观存在，但**不等于**协议已被逆出来。
3. **圈内确有人做到了本地进游戏 + 与 AI 对战**（2026-10-15 用户情报），
   但**方法未公开** → 说明技术可行，只是门槛高、无人分享。

### 2.3 为什么 MSGO 没有开源端（技术层面的必然）

| 原因 | 说明 |
|---|---|
| 客户端被**双层壳**保护 | 外层 Themida + 内层 VMProtect，静态打补丁不可行（本项目的实测结论） |
| **有反虚拟机硬闸** | 本机开着虚拟化时客户端直接拒绝启动 —— 这也解释了为什么私服客户端一定是**魔改/特制**的 |
| **协议加密** | 本项目实测：点击登录后客户端先发 **16 字节高熵、每次不同**的数据包 → 明文凭证被加密，且可能带密钥协商 |
| **引擎未公开** | Headlock 自研，没有公开 SDK，无法像 Unity/UE 那样直接复刻 |
| **逻辑全在服务端** | 52v52 实时战斗、匹配、机体数值全部服务端权威，客户端只是表现层 |
| 版权方仍活着 | 万代南梦宫没有释出任何服务端代码（对比 UCGO 是运营方倒闭后开源） |

## 3. 可参考的邻近项目（重要：协议完全不同，只能借鉴架构/方法论）

### 3.1 SD敢达Online（SDGO）—— 同类里生态最成熟的

> ⚠️ 注意：SDGO 是**Q 版**的《SD高达》，韩国 Softmax 开发、2015-07-31 停运，
> 与 MSGO（写实比例、52v52）**完全是两款游戏**。不要混淆。

| 项目 | 内容 | 可借鉴点 |
|---|---|---|
| `tqgx/SDGO-Ultimate-Repack-v1.2` (GitHub, 2026-01 更新) | **原版客户端 + 模拟器服务端**的完整 repack：14 个服务端程序 + litesql 数据库 + 登录器 + 一键 bat | ⭐ **老网游单机化的标准套路**：多进程服务端 + 独立登录器 + 本地 DB + 一键启动脚本。**这正是我们最终要交付的形态** |
| `redsuns-chan/sdgo-dev-tools` (⭐6, Python) | SDGO 逆向工程脚本集 | 逆向工程的组织方式（解包、协议分析脚本化） |
| `brilam/SDCap` (⭐5, Java, GPLv3) | SDGO 抓包工具 | 专用抓包器的设计思路 |

### 3.2 UCGO（宇宙世纪 高达Online，2005–2007, Dimps）

官方 2007-12-15 停运后，**服务端代码公开**，社区有私人服（`ucgohost.com`）。
→ 这是"老网游复兴"的正面案例，但同样是**另一款游戏**。

### 3.3 GDXSV（PS2/Dreamcast《联邦 vs 吉翁》）

`inada-s/gdxsv`（Go, AGPL-3.0, ⭐21）：完整实现了大厅服 + 对战服分离的架构
（`lbs` 大厅 / `mcs` 对战服，环境变量配置，battlelog 记录）。
→ **架构参考价值最高**：MSGO 也是"大厅 + 战斗服"结构，值得抄它的分层设计。

## 4. 结论与行动建议（按性价比排序）

### ~~建议 A~~（已作废）：接触私服团队

> ❌ **2026-10-15 作废**：私服帖已证实为愚人节活动，"私服团队"不存在，本条无从执行。
> 保留原文仅作记录：原设想是问三件事（客户端是否原版魔改 / 战区列表怎么给 /
> 16 字节协议哪来的）。**现在没有可接触的对象。**

### 建议 B：拿不到端 → 把项目目标下调为"单机可看"

放弃"完整复原在线玩法"，目标改为：**跳过登录 → 进得了大厅/离线场景**。
技术路径（本报告认为的最短路径）：

1. frida hook `WSASend`/`send`，拿到**加密前明文缓冲的地址**；
2. 对该地址下**内存写断点**，回溯出加密函数与密钥；
3. 本地起最小应答服务端，先让客户端"连上、握手成功、进大厅"。

### 建议 C：架构上照抄成熟项目的形态

最终交付物参考 **SDGO-Ultimate-Repack** 的形态：
`服务端多进程` + `独立登录器` + `本地数据库(litesql)` + `一键启动 bat` + `图文教程`，
服务端分层参考 **GDXSV** 的 大厅服/对战服 分离架构。

### ⚠️ 法律与安全提醒

- 依据国家版权局公开定性：网游"私服"属未经授权架设，**违反《著作权法》《计算机软件保护条例》**，
  运营者可面临民事赔偿乃至刑事处罚。
- **自用研究** 与 **公开分发/盈利** 是两个性质完全不同的事。本项目**只做本地离线研究与单机化**，
  **不要公开分发服务端文件、不要运营、不要收费**。
- 从论坛/网盘下载的"私服端"捆绑盗号木马/广告软件是常态（多个来源都提到），
  若真要拿别人的端，**必须在隔离环境里先验毒**。

## 5. 附：解密资源包（`GundamOnline_CHINA_已解密.zip`, ~27GB）的价值评估

> 2026-10-15 用户提供的情报：存在一份**已解密**的国服资源包，约 27GB，
> 含 视频/音频/脚本/设置/模型 等。是否值得下载？结论如下表。

| 内容类型 | 对"跑到登录/进大厅" | 对"单机可看" | 对"还原战斗" | 结论 |
|---|---|---|---|---|
| 模型 / 动画 / 贴图 | ❌ 无 | ✅ 极大（可直接做查看器/重制） | ✅ 渲染必需 | **有价值** |
| 视频 / 音频 | ❌ 无 | ✅ 中 | ~ 中 | 价值一般 |
| **脚本 / 设置 / 表格** | ⚠️ **可能有**（见下） | ✅ 高 | ✅ **参数表来源** | **最值得先确认** |

**关键判断：**

1. **本机客户端里已经有同一批素材，但"读不出来"。** 2026-10-15 复核：
   `data/` 实际是 **~19GB 裸目录素材**（interface 12G / world 2.3G / chara 1.1G /
   sound 1.1G / movie 772M / location 962M / fx / item / pilot / script 34M / settings 7M…），
   但每个文件都是 **`NNNN.dat` 编号 + 高熵内容**。
   实测 zlib（各 wbits）、单字节异或、FPMF 那套**全部解不开**（`server/_probe_dat.py`）。
   → 也就是说，**"已解密 27GB"对我们不是重复内容，而是"把加密素材变成可读素材"**，
   这是本机做不到的。
2. **本机唯一的明文线索 = `list/filelist.dat`**（1707 行 CSV）：能列出全部资产路径、
   大小、SHA1、所属 `data*.zip`（如 `data/interface/main/0045.dat`、
   `data/chara/01/03/0000.dat`、`data/sound/VOICE/npc/2/0004.dat`），
   但**文件名是数字编号**，真正的语义名在**加密的 `.hed` 索引**里。
3. **所以该包的价值边界很清楚：**
   - ✅ 对"**看懂/使用素材**"（做查看器、换引擎重制、给自写服务端喂资源）→ **确实有用**；
   - ❌ 对"**当前唯一卡点（战区列表 / 登录包）**"→ **没用**（不含运行逻辑/协议）；
   - ⚠️ 对"**还原战斗**"→ 只能给素材，**给不了数值与公式**（见下条）。
4. **（2026-10-15 用户情报 3）机体/武器数值与对战计算全在服务端。**
   客户端资源里的表顶多是 UI 展示用的副本，**真正的公式和权威数值不在这里**。

**建议：先要一份文件清单（目录树 / 前几百个文件名）再决定，别盲下 27GB。**
性价比最高的做法是**只下 `script/` + `settings/` 两个子树**（本机对应仅 34MB + 7MB），
看有没有 `authsv / region / zone / protocol` 类线索或 `csv/xml/json/lua` 数据表；
有再考虑全量。
