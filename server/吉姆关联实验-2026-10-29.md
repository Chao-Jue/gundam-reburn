# 吉姆机型ID与模型资源关联实验

用户确认参考资源目录`chara/01/01/0101`为当前版本可用的吉姆。

## 静态链路证据

1. 0xA96070从机体包读取uniqid u64、msma_id u32，之后是时间、昵称、武装和强化等字段，总长299。
2. 0xA832分支0xAC0304调用该解析器，再经vt+0x224 -> 0xAF6EF0 -> 0xA51360 -> 0x5E1A00 -> 0x5DEB20构造持有机体。
3. 0x5DEB20用记录中的msma_id查询DAT_01161F94机型定义表，value=node+0x18；读取value+4并写入构造后机体对象+0x0C。
4. 当前机型定义行解析器0x54EF50将CSV第0列写到value+0，第1列写到value+4。第1列是本次要验证的模型字段候选；不是从299字节机体包直接读取模型号。
5. 资源路径的打包规律由68个带名称的本地配置条目及存在的模型文件交叉验证。101010101 -> group=101、variant=0101、part=01 -> chara/01/01/0101/model/MSM_0101_0101_01.dxg。

上述信息支持间接关联；还需当前运行客户端验证第1列最终是否确实选择该模型。

## 实验内容

`--hangar-experiment gm`临时替换两个下载应答正文：msma/msma_settings.csv、msma/msma_model.csv。不覆盖解码目录中的原文件。

临时机型ID=777001，候选模型ID=101010101，机体实例ID=777000000001。角色机体初始化返回一台无武装的吉姆。所有非关联关键字段均为诊断占位参数，不代表原始游戏参数；不会把该机体保存到saved_hangar.json。

运行：管理员运行`tools/start_gm_experiment.cmd`。它只是在原start_local.cmd前设置当前进程的PILOT_EXTRA，不修改原启动器。关闭后普通start_local.cmd不带该实验参数。

进入格纳库后观察：

- 服务端日志应有两条“GM关联实验定义”下载记录和0xA832。
- 探针gm_id=777001、gm_model=101010101说明机型定义实际加载。
- 探针msma_add增加说明0xA832解析回调执行。
- 模型/机体界面显示结果另行记录。即使解析器成功，也不能直接视为模型渲染成功。

测试：机型ID与模型ID独立、实验默认关闭、正常空机库保持、实验数据不调用资产写入路径、测试机体记录不含模型ID字节。Python语法编译和自动测试通过。当前尚未实际启动此实验。

## 人工标记工具可行性

参考目录已解包出DXG模型和DDS贴图。例如吉姆纹理位于chara/01/01/0101/tex。DXG为自定义容器，文件头DXG，网格名称可读；自由敢达网格含FRDGND标识。不能仅将任意DDS贴到模型上：需要读取网格顶点、索引、UV、材质与纹理引用，并处理子网格/可隐藏部件。

可分两步：先建立资源目录、名称线索、贴图缩略图与人工标签JSON；再完成DXG静态网格导入，提供旋转/缩放预览和材质组合，保存“资源组—模型ID—人工名称—Wiki条目—确认状态”映射。初期静态预览即可支持标记，动画、骨骼与游戏材质效果可后补。该工具尚未实现。
