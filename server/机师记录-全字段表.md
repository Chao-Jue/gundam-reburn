## 2c. 立刻要改的一件事：`troops` 我们一直填错

之前按"线上 0 基"的猜测写 `0=联邦 / 1=吉翁`，参考文档明确是 **1 = 联邦 / 2 = 吉翁**。
换句话说我们发出去的每一条记录，`troops` 都是**非法值**。这很可能就是"客户端认为有机师
→ 走到某处按 troops 索引 → 越界 → 拆连接"的直接原因。

已修正 `fake_auth.pilot_entry` 的注释，并新增变体：

| 变体 | eff | zeon |
|---|---|---|
| `both_t12` | id=5 `TEST` troops=**1** | id=6 `ZEON` troops=**2** |
| `eff_t1` | id=5 `TEST` troops=1 | 全零 |
| `zeon_t2` | 全零 | id=6 `ZEON` troops=2 |
| `both` | 旧数据（0/1，对照组） | |

`tools/start_local.cmd` 当前：`--pilot-variants both_t12,eff_t1,zeon_t2,both --probe-gap 10.0`



反汇编 `FUN_004336a0(card, rec_copy)`（回调里填卡片的那步）第一屏：

```
mov  edi, [esp+0x58]        ; rec_copy（172B）
cmp  dword ptr [edi], 0
setg al                     ; al = (field0 > 0)
xor  al, byte ptr [esi+0x1c] ; 翻转卡片某标志的 bit0
mov  ecx, [edi]
cmp  ecx, 0x77359400        ; = 2,000,000,000
jl   ...
cmp  ecx, 0x7d2b7500        ; = 2,100,000,000
jg   ...
or   al, 8                  ; 落在 [2e9, 2.1e9] 区间 → 置 bit3
```

- 如果线偏移 0 是 `pilot_id`，那"id 落在 20 亿~21 亿之间就置某标志"完全说不通；
- 如果它是**时间戳/序号**（10 位数），这个区间就有意义了。
- 我们现在一直往这里写 `5`。

⇒ 参考文档把它命名为 `pilot_id`，但这段比较仍然解释不了。
**可检验的假设**：`pilot_id` 可能不是从 1 开始的小整数，而是"时间戳派生的大数"。
下一轮如果 `both_t12`（troops 修正）仍不通过，就把 `pilot_id` 换成 2e9 区间内的值再试一次。

## 5. 这套表能解释的与不能解释的

- 能解释：为什么 817 字节刚好被完全消费（58 个字段逐项相加 = 398，两侧 + 尾部 13 = 817）；
- 不能解释：为什么"有机师"之后客户端会拆掉会话 —— 因为**语义层几乎全是空白**，
  我们只是"按尺寸对上了"，并没有"按含义对上了"。
