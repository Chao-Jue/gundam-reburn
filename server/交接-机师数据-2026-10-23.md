## 2. 已确证的事实（可以直接依赖）

### 2.1 链路

```
表阶段(65 张) → auto_advance poke 下载器 → 步骤机 case5 通过
  → case7: 客户端发 0x60CD (send_pilot_list_get)，界面切「正在取得机师数据」
  → case8: 等 [game+0x10615] == 1
      ← 由 recv_pilot_list_get_r 解析成功后调 vtable+0x80 → FUN_00439190 置位
  → 离开等待界面
```
- 步骤机 `FUN_0043b530`，`*(this+4)` = 步号；游戏对象 `DAT_01161f28`，下载器在 `+0x580`
- 重置器 `FUN_0043bf50`（也会销毁下载器）
- **`FUN_00439190` 没有任何提前 return**（146 行，唯一 return 在末尾）⇒ 只要被调用，
  `+0x10615` 必被置 1 ⇒ **标志没置 = 解析没走完、没调到 vtable+0x80**

### 2.2 帧层（文档权威 + 我们实测一致，**这块不用再怀疑**）

来源：`refs/msgo-doc/reverse-login-chain/formats/全链报文总表.md` §0

- 帧头 `4B` 小端 = 本帧明文长度 n；`n == (full<<4)|tail`
- **帧类型 `type = buf[0] >> 4`**：0=数据帧（低 2 位 k 决定长度字段宽度 0..3B，载荷→`vt[21]`）；
  **1=对端时间戳(9B)；2=RTT(9B)**；3=控制帧(5B)；4=安全层；≥5 非法
- 内层报文 = `u16 ID(小端) + 体`；单帧可含多条
- 单帧明文上限 16366B，超了服务端侧 clamp 自动分帧
- 加密 = Camellia-128 counter，无复位点

我们的出站 `[0x00][len][u16 op][body]`（`_kind0` + `build_inbound_frames`）**符合 type0 数据帧**。

### 2.3 我们客户端里 `0xE13A` 的解析代码

- 记录读取器 `FUN_00a956f0`，被 `0xac305f` 等调用
- **真正的机师解析段在 `0xacfexx`**（hook 实测 ret=0xacfe6c..0xacffbf），
  不是 `--callers` 给出的 `0xac2fxx`（那是同族的另一条命令）
- 读取器原语：`0xa5a310`=读 u32；`0xa5a330`=读 u16；`0xa5a360`=读 u8；
  `0xa5a270`=数组头（thiscall，ECX=param_1）；`FUN_00a956f0`=读一条机师记录
- 读取器结构体 = `{cursor, end}`，`end - cursor` 即可读字节数

## 5. 唯一未解的核心矛盾（下一步从这里开始）

hook 在发 **845 字节正文**时读到：

```
#2 u32  cur=0x32d17b2d  end=0x32d17b7a  remain=0x4d (77)
#3 rec  cur=0x32d17b31  end=0x32d17b7a  remain=0x49
#4 rec  cur=0x32d17b77  end=0x32d17b7a  remain=0x03   ← 第二条记录读不下
```

**客户端认为这条消息只有 77 字节正文**，而我们发了 845。

原始字节（hexdump）：
```
... 08 01 | 4f 00 | 3a e1 | 00 00 ...
             长度79   opcode
```
`0x4F = 79 = 2(opcode) + 77`。**而 845 的低字节正是 0x4F** ⇒ 高度怀疑
**长度字段只被读到 1 字节**。

两种可能，二选一：
- (a) 服务端 `_kind0` 在 n>0xFF 时用的 3 字节头（`01 lo hi`）客户端不认；
- (b) 客户端确实只读 1 字节长度，**那所有 >253 字节的正文都需要另一种封装方式**。

**验证方法（下次第一件事）**：
1. 给 `fake_auth` 的 probe 分支加日志：打印实际发出的**前 16 字节 hex**（已加好，见 §7）；
2. 同时用 `pilot_hook` 打印 `[pcur]/raw0/raw4`（已加好）；
3. 两边一对照就能定论：若服务端发的是 `014f03…`，而客户端按 79 解析 ⇒ 就是 (b)。

> ⚠️ 用 hook 时**只挂 `0xa956f0`**（冷函数，一次登录 2 次调用），
> 绝对不要再挂 `0xa5a310`/`0xa5a270`（热函数，会连续闪退）。

## 8. 今天踩过的坑（省得下次再踩）

1. `argparse` 的 `type=int` **不认 `0x` 前缀** → 一律用 `int(s,0)`
2. 改 `start_local.cmd` 必须**保持 CRLF + 纯 ASCII**，且改完要看一眼
3. 改 `run_hooked.py` 的 CLI 参数后**必须跑一次 `--help`** 验证注册成功
   （我曾因引号不匹配静默失败，导致客户端起不来）
4. 客户端有**概率性崩溃**（启动期 / 表阶段早期），重跑 2~3 次能过，不是代码问题
5. `L0:0` / `A 2:0` 是客户端自绘状态码，不是协议字段
6. 判据永远用「有没有新入站报文」，不要用「连接是否断开」
