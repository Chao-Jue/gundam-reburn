# 5.0.0.33 客户端接入补丁（本地测试 IP 版）

给 **MSGO 5.0.0.33 国服客户端**用的接入包，配合本仓库的自建服务端使用。解决两件事：

1. 把客户端的认证服务器地址从官方清单改到自建服务端（`authsv.csv` / `authsv_stg.csv`）。
2. 客户端不会自己写「强化券面板数据源」，导致券名/数量空白、强化请求带不出券 id；
   启动脚本在游戏起来后一次性补 11 个券 id 到内存。

> 本目录就是补丁包解压后的内容，**目录结构与压缩包根目录一一对应**。
> 仓库 `.gitignore` 忽略 `*.zip`，因此提交的是文件树而不是打包文件。

---

## ★★ 两条最容易踩坑的提醒 ★★

### 1. IP 写死为 `127.0.0.1:30000`，换部署环境必须同步改 4 处

本包只适用于「服务端和客户端在同一台机器」的本地测试。换成局域网 / Tailscale 等部署时，
下面 4 处必须**同值**，只改一处会连不上，而且客户端不会给出任何错误提示：

| # | 位置 | 改法 |
|---|---|---|
| 1 | `data/settings.hed` + `data/settings/0000.dat` 里的 `authsv.csv`、`authsv_stg.csv` | 用 `patch_authsv_ip.py` 等长改写，**不要**直接改字节长度 |
| 2 | `启动客户端-远程.cmd` 里的地址文案（2 处） | 文本替换 |
| 3 | `说明.txt` 里的地址文案 | 文本替换 |
| 4 | 服务端 `server/fake_root/launcher/authsv.csv` 的 `zone_host` | 服务端侧，不在这个目录里 |

`patch_authsv_ip.py` 会自动备份原文件，且先试算全部记录、确认都能等长才动字节。

### 2. 补丁必须放在**游戏根目录**（与 `GundamOnline_CHINA.exe` 同级）

压缩包内所有文件已经在根目录：直接「解压到游戏安装目录」覆盖即可。
**不要**新建一层子目录再解压 —— 会变成
`游戏目录/msgo50033-client-dist/data/...`，客户端读不到 `./data/`，表现为启动失败或回连官方。

`启动客户端-远程.cmd` 用 `%~dp0` 自定位；放错目录会打印中文错误并 `exit /b 2`，
不写任何字节，方便排查。

## 用法

1. 先启动本仓库的自建服务端（默认 `127.0.0.1:30000` / `:30001`），确认 30000 在 LISTENING。
2. 把本目录内 4 个文件/目录整体复制到客户端 5.0.0.33 安装目录，与
   `GundamOnline_CHINA.exe` 同级；提示覆盖时选「是」。
   只会覆盖 `data/settings.hed` 与 `data/settings/0000.dat` 两个接入配置文件，不动其它游戏资源。
3. 双击 `启动客户端-远程.cmd`。**不要**双击游戏主程序 —— 必须带 `cpsoff` 参数，
   否则会弹「发现错误 / 内部错误码 49236」。
4. 出现登录框后输入测试账号即可进入。补券结果看游戏目录下的 `ticket_src_patch.log`，
   出现 `[RESULT] OK filled 11 tickets` 或 `[RESULT] OK ready` 即成功。

改 IP 的标准流程：

```bat
python patch_authsv_ip.py status --client-root "<游戏安装目录>" --fpmf-dir "<含 fpmf.py 的目录>"
python patch_authsv_ip.py patch  --client-root "<游戏安装目录>" --host 127.0.0.1 --port 30000
```

## 实现路径

| 文件 | 作用 | 实现要点 |
|---|---|---|
| `data/settings.hed` | FPMF 资源索引 | 每条记录 `(offset, size, resource_key)`；改写后必须重算 `resource_key`，否则客户端忽略该资源 |
| `data/settings/0000.dat` | 归档正文（7.2 MB） | `authsv.csv` / `authsv_stg.csv` 在此包内；由原版客户端归档**等长**改写 IP 字段而来 |
| `patch_authsv_ip.py` | 等长 IP 改写工具 | 替换数据行 IP/端口，长短差从「第一个数据行组名尾部空格」扣/补；先全量试算、备份原文件、原地覆盖 + 更新索引键 + 复核 |
| `启动客户端-远程.cmd` | 唯一入口 | `%~dp0` 自定位 → 目录校验 → `GundamOnline_CHINA.exe ./data/ cpsoff` → 拉起内嵌补券脚本 |
| `说明.txt` | 玩家说明 | 含上面两条提醒、验证方法、包内容 |

### 为什么必须等长

`0000.dat` 是一整包顺序资源，`settings.hed` 只存每条记录的 `(offset, size, resource_key)`。
任何一条记录的字节长度变化都会让后续所有记录的 offset 整体错位，客户端读到乱码甚至无法启动；
FPMF 没有空洞/重定位机制。实测 `127.0.0.1`(9 字符) ↔ 更长的 IPv4 地址
（如 `192.168.100.92`，14 字符）双向都成立。
`resource_key` 只依赖明文首字节与长度，改写后要用 `calculate_resource_key()` 同步重算。

### 启动脚本的两个硬约束

- **GBK 编码 + 全 CRLF**：纯 LF 时 `cmd.exe` 解析错乱（`goto` 标签定位失败、带括号 `if(...)` 块失效），
  表现为「窗口一闪、客户端根本没起来」。
- 末尾 `==== PS_PAYLOAD_BEGIN ====` 之后是明文 PowerShell payload，
  cmd 运行时把它抽到 `%TEMP%\mgol_ticket_src.ps1` 再执行，玩家无需管理额外文件。
  不用 `-EncodedCommand`（被本机策略拦过），payload 全 ASCII，函数名避开 `R`/`RM` 别名。

### 强化券补丁的内存链

纯协议/表链路判负：面板数据源 `*(*(0x1161F80)+0x50)` 在客户端里被 510 处引用、
**全部是读、0 个写入者**，所以只能写内存。payload 沿这条链读到 44 B 缓冲
（11 × u32），若全零则写入 11 个券 id：

```
80100001 80200001 80300001 80400001 80500001 80600001
80700001 80800001 80900001 81000001 81100001
```

写完立即退出：不常驻、不改游戏文件、不联网、不消耗券；券的持有数量仍由服务端物品栏下发。
启动动画期间注入也不会被清掉，进大厅后依然有效；每次重启客户端自动再补一次。

## 兼容性 / 风险 / 回滚

- 只针对 **5.0.0.33** 客户端，别的版本 `0000.dat` 布局不同，不能直接套。
- 覆盖前请自行备份原 `data/settings.hed` 与 `data/settings/0000.dat`；
  `patch_authsv_ip.py` 也会自动备份到 `data/_msgo_ipbackup_<时间戳>/`。
- 回滚：把备份的两个文件拷回 `data/` 即可，启动脚本不影响客户端其余功能。
- 若维护者不希望仓库引入 7.2 MB 的客户端派生二进制，可以只保留
  `README.md` + `patch_authsv_ip.py` + `启动客户端-远程.cmd` + `说明.txt`，
  由使用者在自己的客户端副本上跑 `patch_authsv_ip.py` 生成两个 data 文件。

## 验证记录（5.0.0.33 真机）

| 层 | 结果 |
|---|---|
| 静态 | 两表 `authsv.csv` / `authsv_stg.csv` 解密复核：全部数据行 `127.0.0.1:30000`，`calculate_resource_key()` 与 HED 记录一致 |
| 编码 | 启动 cmd 6256 B，GBK 可解码、全 CRLF、无残留原 IP、payload 标记完整 |
| 打包 | 4 个条目全在压缩包根目录；原分发包未被改动 |
| 运行 | 客户端起登录框、进大厅无 `[5:13]`；补券日志出现 `[RESULT] OK filled` |

## 已知限制

- 地址写死 `127.0.0.1`，跨机部署需按上文「4 处同值」自行替换。
- 补券只修面板数据源；若物品栏下发或图标表链路没配好，面板仍可能显示 0 个/空白。
- 启动脚本文件名沿用 `启动客户端-远程.cmd`（与实际分发包保持一致），文案已标为本地测试用途。
