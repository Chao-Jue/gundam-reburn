MSGO 5.0.0.33 客户端接入包（本地测试版 · 提交给上游）
================================================

服务端入口：127.0.0.1:30000（本机回环；需先启动 gundam-reburn 自建服务端）

★★ 提交版的两条硬提醒 ★★
1. IP 不是通用的。本包写死 127.0.0.1:30000，只适用于「服务端与客户端同一台机器」的本地测试。
   换成其它部署（局域网 / Tailscale）时，必须同步改 4 处同值：
     - 本说明与启动 cmd 里的地址文案
     - data/settings.hed + data/settings/0000.dat 内的 authsv.csv / authsv_stg.csv
       （用附带的 patch_authsv_ip.py 等长改写，不要直接改字节长度）
     - 服务端认证清单 fake_root/launcher/authsv.csv 的 zone_host
       （本仓库在 server/fake_root/ 下，50033 服务端在 dataset/fake_root/ 下）
   只改其中一处会连不上，而且不会有任何报错提示。
2. 补丁文件必须放在游戏根目录，即与 GundamOnline_CHINA.exe 同一层。
   压缩包内文件已经在根目录，直接「解压到游戏安装目录」即可；
   不要新建一层子目录再解压（会变成 游戏目录/msgo50033-client-dist/...，客户端读不到）。
   启动 cmd 用 %~dp0 自定位，放错目录会中文报错并退出、不写任何字节。

【给玩家的一句话】
   把本包内所有内容覆盖到游戏根目录（与 GundamOnline_CHINA.exe 同级），
   然后双击「启动客户端-远程.cmd」。启动游戏 + 补上强化券数据，一次完成。

【接入步骤】
1. 先启动自建服务端（默认 127.0.0.1:30000 / :30001），确认 30000 端口在 LISTENING。
2. 把包内内容整体复制到客户端 5.0.0.33 的安装目录，
   即与 GundamOnline_CHINA.exe 同级；提示覆盖时选择「是」。
   ※ 只会覆盖 data/settings.hed 与 data/settings/0000.dat 两个接入配置文件，
     不动其余任何游戏资源。想还原时用原安装包或向分发者要原版文件。
   ※ 补券逻辑已内嵌在「启动客户端-远程.cmd」里，
     **不需要额外的补丁文件**，运行时也不联网拉配置。
3. 双击「启动客户端-远程.cmd」。不要双击游戏主程序——必须带 cpsoff 参数，
   否则会弹「发现错误 / 内部错误码 49236」。
   ※ 必须用本包这一份 cmd 覆盖原来的启动脚本；旧脚本不带补券功能。

【验证】
   客户端启动后应出现登录框；输入测试账号即可进入。
   连不上时先在本机执行：ping 127.0.0.1
   补券结果日志：游戏目录下的 ticket_src_patch.log
   （出现 [RESULT] OK filled / ready 即成功）

【包内容】
   data/settings.hed        已把认证服务器指向 127.0.0.1:30000
   data/settings/0000.dat   同上（认证 CSV 在此归档内）
   启动客户端-远程.cmd       唯一入口：启动游戏 + 内嵌补券（自动带 cpsoff）
   说明.txt                 本文件

【强化券补丁说明】
   5.0.0.33 客户端不会自己写「强化券面板数据源」，导致券名/数量空白、
   强化请求带不出券 id。启动 cmd 会在游戏起来后异步执行一次内存写入补上
   11 个券 id，写完立即退出，不常驻、不改游戏文件、不联网、不消耗券。
   券的持有数量来自服务端物品栏，补丁不改动数量。
   补券代码以明文内嵌在本 cmd 末尾，运行时在系统临时目录生成一次性
   脚本执行，玩家无需管理任何额外文件。
   用户在启动动画期间注入也不会被清除，登录进大厅后依然有效；
   每次客户端重新启动都会自动再补一次，无需手动操作。
   若面板仍显示 0 个/空白，属物品栏下发或图标表链路，请联系分发者。
